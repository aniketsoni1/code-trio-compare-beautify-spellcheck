# Code Trio v0.2.0

**Code Trio – Compare Beautify Spellcheck** bundles three everyday tools — code
compare/diff, a code-aware spell checker, and a beautifier — into one
deterministic, offline, privacy-respecting package. It ships as a cross-platform
CLI (`code-trio`) and a VS Code extension, both built on one shared TypeScript
core.

Everything runs locally. There are no network calls and no telemetry.

## Highlights

### Three-way merge finally reaches the product

The diff3 engine shipped in v0.1.0, but nothing could reach it — there was no CLI
command and no editor command. "Three-way diff" was true of the engine and false
of the product. v0.2.0 adds `code-trio merge` and six editor commands with
conflict navigation, accept ours / theirs / both / base, manual resolution, and a
preview before anything is written.

`code-trio merge <file> --git` reads git's conflict stages directly, so it works
on a real conflicted working tree with no manual extraction. Saving writes to a
**new file by default**, requires an explicit confirmation to overwrite the
original, and **refuses outright while any conflict is unresolved** — a file
containing conflict markers looks merged and is not. Git staging is never
touched.

### Spell checking that is worth leaving on

URLs, file paths, hashes, UUIDs, hex values, versions, timestamps, base64 blobs
and template placeholders are suppressed *before* any word is extracted.

Measured on a fixture of twelve realistic comment lines: **28 diagnostics before,
9 after**. Every survivor is either a genuine misspelling or an ordinary word
missing from the ~1,200-word base list. The suppression pass costs no measurable
time (`docs/performance.md`).

Word extraction is now Unicode-correct, so accented words and non-Latin scripts
are handled rather than mangled, and contractions stay whole.

### Per-folder dictionaries

Six scopes with documented precedence: session, workspace folder, workspace,
user, technical, base. A scope can **reject** a word with a `!` prefix, and a
rejection stops the lookup — which is what makes precedence mean anything rather
than being purely additive. One package in a monorepo can refuse a word the
shared repository dictionary accepts.

### External formatters, honestly reported

Ruff, Black, gofmt, rustfmt and clang-format are used **when you already have
them installed**. Nothing is ever downloaded.

More importantly, a missing formatter now *says so*. Previously, pressing
Beautify on a Python file with no Ruff installed fell through silently to the
whitespace normalizer, so you got trailing-whitespace trimming and reasonably
concluded Ruff had run and found nothing. Now you get the name of the executable
that was looked for and a button that opens the right setting.

### A results panel that exists

The v0.1.0 "unified results panel" was three static rows in a tree view — which
is why the README's claim of a "strict webview Content Security Policy" described
something that did not exist. v0.2.0 ships a real webview: per-tool tabs,
severity counts, search, five sort orders, full keyboard navigation, copy, and
Markdown/JSON export, with state that survives the panel being hidden.

## Compare changes

- Two Explorer selections, selection against clipboard, buffer against the
  version on disk, and previous revision (`HEAD~1`).
- Unicode-correct word and grapheme refinement.
- Common prefix/suffix trimming before the Myers search — comparing two identical
  20k-line files is now *faster* than diffing them.
- Binary, oversized and minified input refused or downgraded with an explicit,
  displayed reason instead of a silently empty diff.
- Line-ending fidelity: files identical apart from line endings say so.
- Markdown and side-by-side output formats.
- Cancellation.

## Spell changes

- Noise suppression (above), Markdown front matter / code / link handling, and
  template-interpolation skipping.
- Six dictionary scopes; session ignore list that writes nothing.
- Suggestions rank transpositions and adjacent-key typos first, prefer technical
  terms, and preserve capitalisation.
- Whole documents skipped when binary, generated, minified or oversized.

## Beautify changes

- Capability-aware adapters with availability, version and resolved executable
  path reported.
- Beautify Entire Workspace behind a modal confirmation naming the file count.
- Batch formatting with progress, cancellation and partial-failure reporting — a
  single unparseable file no longer aborts the run.

## CLI changes

New commands: `merge`, `report`, `dictionary`, `formatters`, `exit-codes`.

A **stable, documented exit-code contract** that distinguishes "the tool worked
and found something" (1) from "the tool could not do its job" (2+). Previously
`2` meant both "invalid arguments" and "no files matched", so a script could not
tell a typo from an empty glob.

Run `code-trio exit-codes` for the table.

## Privacy and security

No network calls, no telemetry, all processing local. Verified by grep across
shipped source, by a manifest test asserting no telemetry contribution point, and
by a CI job that fails if a network client appears.

Security work in this release:

- Git refs validated against an **allowlist**, rejecting anything git would parse
  as an option — `--upload-pack=` is a code-execution primitive.
- Git and formatter child processes run with a **minimal environment**, so a
  hostile workspace cannot steer them through `GIT_EXTERNAL_DIFF`,
  `GIT_SSH_COMMAND`, `NODE_OPTIONS`, `PYTHONSTARTUP` or `RUSTC_WRAPPER`.
- Every child process has a timeout with a `SIGKILL` watchdog and bounded output.
- Configured formatter paths must be absolute and executable.
- A formatter returning empty output for a non-empty document is refused rather
  than emptying the file.
- Webview under `default-src 'none'` with per-load nonces, no `unsafe-inline`, no
  remote origin. Inbound messages validated at runtime against a schema.
- Write operations remain blocked in untrusted workspaces.

Full threat review, including five honestly recorded accepted risks:
`docs/security-review.md`.

## Upgrade instructions

No action required. v0.2.0 is backwards compatible:

- `codetrio.json` files continue to work; every new key has a default.
- `.codetrio/dictionary.txt` keeps its path and meaning.
- Existing settings keep their names. Nine settings that were previously read and
  then discarded now actually take effect — if you had set
  `codeTrio.format.printWidth` and seen no change, it will now apply.
- External formatter discovery is on by default. Set
  `codeTrio.externalFormatters.enabled` to `false` to keep v0.1.0 behaviour.

No breaking changes.

## Known limitations

- **The clean-profile installation test was not executed.** The environment that
  produced this package has no VS Code binary. Manual steps are in
  `artifacts/v0.2.0-verification.md`; the package must not be described as
  install-tested until they have been run.
- The bundled base dictionary is ~1,200 words, so ordinary English words are
  sometimes flagged. Shipping a full lexicon would add megabytes and a licensing
  question; downloading one would break the offline guarantee.
- External formatters are used only when already installed, and Code Trio does
  not verify the identity of an executable you configure.
- Character-granularity diffs of very long lines are slow by nature; minified
  input is downgraded to line granularity automatically.
- No Language Server package yet.
- Benchmarks measure engine throughput, not extension activation time.
