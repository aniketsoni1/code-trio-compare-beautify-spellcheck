## Why this release exists

The Marketplace rejects a re-upload of an existing version, and `0.2.0.1` is not
valid — VS Code requires strict three-part semver. `0.2.1` is also the honest
label: this build genuinely fixes a user-facing bug and a batch of inaccurate
Marketplace metadata that shipped in 0.2.0.

## Fixed

### Git operations failed on symlinked paths

`gitShow` and `conflictStages` returned null for files reached through a
symlinked path, so **compare-against-git-ref and merge-from-git-stages did not
work** for affected repositories.

`git rev-parse --show-toplevel` always reports a *resolved* path, while the path
a caller supplies may contain symlinks. Comparing the two without canonicalising
made a legitimate file inside the work tree look like an escape attempt, and the
containment guard rejected it.

Who this affected:

- **macOS**, for any repository under a symlinked directory. `/var` is a symlink
  to `/private/var`, so anything under the temp directory failed outright, and
  many ordinary developer setups reach their repositories through a symlink.
- **Windows**, through 8.3 short names (`RUNNER~1` versus `runneradmin`).
- Linux was unaffected only because its paths are typically not symlinked.

Both sides are now canonicalised with `realpathSync.native` before the relative
path is computed. The containment guard is unchanged in strength: `/etc/passwd`,
`../../` traversal and any path outside the work tree are all still refused, and
that is now asserted *through* a symlinked path as well.

Caught by the cross-platform CI job added in 0.2.0, on its first real run.

### Two test files were invisible to the CI offline audit

Raw control bytes — a NUL, and a ZIP magic number used to build binary fixtures —
made two test files binary as far as `grep` is concerned, and `grep` skips binary
files silently. The CI job that scans shipped source for network clients and
telemetry SDKs was therefore not reading them, and nothing reported it.

Rewritten as escapes, with identical string values, plus a repository-wide guard
asserting no raw control characters, valid UTF-8 and no byte-order mark.

## Documentation

The extension's own README and manifest metadata are what users read on the
Marketplace, and both still described the v0.1.0 feature set:

- Description said "three offline dev tools"; there are four, and three-way
  merge — the headline of 0.2.0 — was absent entirely.
- The README listed 10 of 32 commands. Every merge, dictionary and formatter
  command was missing, along with four of the seven compare workflows.
- Keywords omitted `merge conflict`, `three-way merge`, `ruff`, `gofmt`,
  `rustfmt` and `dictionary`, so searches for any of those would not find it.
- The Workspace Trust description named two write operations; saving a merge is
  a third.
- The welcome view offered three buttons and no route to merge.
- `codeTrio.spellAddWord` was still titled "Add Word To Project Dictionary"
  although it now asks which scope to write to.
- `projectDictionaryPath` was described as "the shared project dictionary",
  implying it was the only one.

## Known limitations

Unchanged from 0.2.0, with one addition worth stating plainly:

- **The clean-profile installation test was not executed.** The environment that
  produced this package has no VS Code binary. Manual steps are in
  `artifacts/v0.2.1-verification.md`.
- **The screenshots in the extension README are still the v0.1.0 renders.** They
  show a results panel that no longer exists — a tree view, where 0.2.0 replaced
  it with a webview. `docs/media.md` has the capture checklist.
- The bundled base dictionary is ~1,200 words, so ordinary English words are
  sometimes flagged.
- External formatters are used only when already installed, and Code Trio does
  not verify the identity of an executable you configure.
- No Language Server package yet.
